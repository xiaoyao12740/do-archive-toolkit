# 实现原理 / Architecture & Implementation

本文说明 do压缩包 在 Windows 与 Android 两端的技术实现，供学习与二次开发参考。

---

## 一、总体设计
两端目标一致：**把"选目标 → 识别格式 → 解压/压缩 → 处理分卷与密码 → 递归套娃 → 清理/扁平化"做成自动化流水线**，
并对非专业用户隐藏命令行复杂度。

```
                ┌──────────── 共享的领域概念 ────────────┐
                │ 格式识别 / 分卷组 / 密码池 / 递归队列     │
                │ 删除原件开关 / 结果扁平化 / 日志          │
                └─────────────────────────────────────────┘
                  ▲                                   ▲
   Windows: Python + CLI 封装              Android: Kotlin + 原生库(JNI)
   7z.exe / lz4.exe / Rar.exe              libarchive / unrar + Room + Service
```

---

## 二、Windows 端（`windows/do_extract.py`）

### 技术栈
- **纯 Python 3 标准库**（os / subprocess / pathlib / tempfile / argparse / msvcrt / re 等），无第三方 pip 依赖；
- 通过 `subprocess` 调用外部命令行工具完成真正的压缩解压：
  - `7z.exe`：主力，处理 zip/7z/rar/tar/gz/bz2/xz 等几乎全格式（RAR 解压依赖 7z 内置的 unrar 代码能力）；
  - `lz4.exe`：专解 `.lz4` 单层，解开后若内部仍是压缩包再交回队列；
  - `Rar.exe`（可选，本机装了 WinRAR 才有）：用于创建 RAR。
- **PyInstaller `--onefile`** 打包成单文件 exe，内嵌 Python 运行时。

### 关键机制
1. **真实格式识别（不看后缀）**：读文件头魔数
   - `PK\x03\x04`=zip，`Rar!\x1a\x07`=rar，`7z\xbc\xaf…`=7z，
     `\x04\x22\x4d\x18`=lz4 frame，偏移 257 处 `ustar`=tar，`\x1f\x8b`=gz，`BZh`=bz2，`\xfd7zXZ`=xz。
   - 改后缀伪装成 jpg/dat 的包也能认；必要时用 `7z t` 在临时目录做容错探测。
2. **分卷组（ArchiveGroup）**：用正则把 `partN.rar`、`.zNN`、`.zip.NNN`、`.7z.NNN`
   归一为"入口 + 全部成员"，只对入口解一次，删除时整组删，避免重复/残留。
3. **递归队列**：BFS `deque`，每次解开后扫描产物，仍是压缩包就入队继续，实现"套娃解到底"。
4. **密码池 + 掩码输入**：
   - 全局密码列表对所有待解包自动复用；
   - Windows 用 `msvcrt.getwch()` 逐字符读取，屏幕只回 `*`，支持退格 / Esc 清空 / Ctrl+C；
   - 依据 7z 输出的 `Wrong password` / `Cannot open encrypted archive` 等关键字判定是否密码错误；
   - `q/exit` 退出做二次确认（因为它们也可能就是密码本身）。
5. **扁平化**：解压先落在包旁的临时目录，再把内容 `move` 到包同级——
   用户只看到"内容 + 包名"，不用点很多层文件夹。
6. **失败归类**：需要密码的整组移到 `未解压_需要密码/`，其它失败移到 `未解压_其他原因/`，并写详细日志。
7. **工具自动探测优先级**：随包 `tools/` → 注册表（7-Zip 安装路径）→ 常见安装目录 → PATH。
8. **双语 i18n**：所有界面文案走 `I18N["zh"/"en"]` 字典，菜单/命令行 `--lang` 均可切。

### 三种形态的关系
- `do_extract.py` 是唯一核心；
- `解压.bat` / `压缩.bat` 是设置 UTF-8 代码页后的薄启动器（支持 `%*` 拖拽传参）；
- `do.ps1` 用 PowerShell 参数做同名封装；
- `do压缩包.exe` 是同一份 py 的 PyInstaller 产物，运行时在**自身目录**找 `tools/`。

## 三、Android 端（`android/source/`）

### 技术栈
- **Kotlin 原生**，minSdk 覆盖到 Android 14–17 目标设备；
- **解压引擎** `engine/ArchiveEngine.kt`：经 JNI 调用 **libarchive**（zip/7z/tar/gz/bz2/xz/lz4…）
  与 **unrar**（`UnrarBridge.kt`，RAR 专有格式）；`LibArchiveBridge.kt` 负责 native 桥接；
- **压缩引擎** `engine/CompressEngine.kt`：生成 zip（支持 AES-256）、7z、分卷、加密层数控制；
- **后台任务** `service/ExtractService.kt`：前台 Service + 通知栏进度（当前包名 / 总进度），批量并发；
- **密码库** `data/PasswordDatabase.kt`：Room(SQLite)，分"加密本 / 解密本"两表，
  同库唯一约束（去重），移动操作为"复制"语义；
- **界面**：`MainActivity`（解压/压缩主界面）、`PasswordActivity`（双密码本）、
  `SettingsActivity`（设置/主题/图标）、`MyApp`（Application 全局）。

### 关键机制
1. **统一主题系统**：`themeMap` 用 6 元组 `(背景,主文字,次要文字,强调色,顶栏,卡片)`描述 12 个主题；
   `recolorTheme` 递归遍历视图树，**无条件**按主题重设背景/卡片/按钮，
   并为按钮缓存原始 tint（`btnOriginalTint`），保证从"夜间黑"切回浅色时按钮正确恢复、不残留。
2. **调度档位**：低 / 中 / 高映射到不同并发线程数与 IO 吞吐；"自动"读取设备 CPU 核数 / 内存动态决定；
   "自定义"允许在 1–16 之间手填并做设备合理范围钳制。
3. **目标选择**：系统 SAF / DocumentFile，单文件与目录 Tree 两种 URI 都走同一套扫描。
4. **扁平化**：与 Windows 同思路，递归解出嵌套后只保留内容 + 首个包名目录。
5. **桌面图标**：用 `activity-alias`（AliasRock/Pc/Monitor/Phone/Thinker）配合
   `PackageManager.setComponentEnabledSetting` 启用其一、禁用其余——这是安卓**官方支持**的
   "多内置图标切换"方案；图标必须是编译期内置资源，因此不支持任意照片当桌面图标（系统限制）。

## 四、安全与隐私
- 密码仅本地保存（Windows 不落盘；Android 存 App 私有 Room），屏幕掩码、日志打码；
- 两端默认都**不**删除原文件，删除是显式开关且只在确认成功后执行；
- Android 端不申请联网权限，全部处理离线完成；
- 本程序只是第三方 CLI / 原生库的编排层，不包含 7-Zip / WinRAR / lz4 的专有源代码。

## 五、目录对照
| 关注点 | Windows | Android |
|---|---|---|
| 入口 | do_extract.py / *.bat / do.ps1 / exe | MainActivity / ExtractService |
| 解压 | 7z.exe + lz4.exe | libarchive + unrar (JNI) |
| 压缩 | 7z.exe（rar 用 Rar.exe） | CompressEngine |
| 密码 | 内存密码池 + 掩码输入 | Room 双库 + 唯一约束 |
| 并发 | 串行队列（CLI） | 前台 Service + 可调配额 |
| 主题 | 终端文本（双语） | 12 主题全页面联动 |
